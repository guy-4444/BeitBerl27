# תרגיל בית ב-Java: מערכת מלאי ומכירות לחנות

**נושא:** מחלקות, מערכים, לולאות ופעולות על אובייקטים  
**משך עבודה מומלץ:** כשעתיים  
**אופן הגשה:** פרויקט Java הכולל שלוש מחלקות וקובץ `README.md` קצר המתעד את הבדיקות שביצעתם

## מטרת הפרויקט

חנות קטנה מעוניינת לנהל מוצרים, לבדוק איזה מוצרים נמצאים במלאי ולרשום מכירות.

תבנו מערכת פשוטה הכוללת:

- מערך של אובייקטים מסוג `Product[]` לשמירת המוצרים בחנות.
- מערך פרימיטיבי מסוג `int[]` לשמירת מספר היחידות שנמכרו מכל מוצר.
- שימוש בלולאות `for` ו-`while`.
- שימוש ב-`break` וב-`continue` במקומות המתאימים.
- בנאים, `private`, `public`, `getters` ו-`setters` עם בדיקות תקינות.
- מזהה אוטומטי לכל מוצר באמצעות משתנה `static`.

**כל חלקי הפרויקט הם חובה.** אין צורך בממשק גרפי או בקלט מהמשתמש. את פעולות הבדיקה יש להריץ מתוך `main`.

## חלק א: המחלקה `Product`

צרו מחלקה המייצגת מוצר בחנות.

### שדות

| שדה | טיפוס | משמעות |
| --- | --- | --- |
| `id` | `int` | מספר מזהה ייחודי למוצר |
| `name` | `String` | שם המוצר |
| `price` | `double` | מחיר יחידה |
| `stock` | `int` | מספר היחידות הזמינות במלאי |
| `nextId` | `static int` | המזהה שיקבל המוצר הבא |

כל השדות יהיו `private`. ערכו ההתחלתי של `nextId` יהיה `1000`.

### בנאי

צרו בנאי המקבל שם מוצר, מחיר וכמות התחלתית במלאי:

`Product(String name, double price, int stock)`

הבנאי יקצה מזהה אוטומטי למוצר ויקדם את `nextId`. יש להבטיח שהמוצר ייווצר עם נתונים תקינים.

לצורך התרגיל, אם אחד הערכים המתקבלים אינו תקין, יש להשתמש בערכי ברירת המחדל הבאים:

- שם ריק או `null`: השם `Unknown`.
- מחיר קטן או שווה ל-0: מחיר `1.0`.
- מלאי שלילי: מלאי `0`.

### פעולות

ממשו את הפעולות הבאות:

1. `getId()`, `getName()`, `getPrice()`, `getStock()` מחזירות את ערכי השדות המתאימים.
2. `setName(String name)` משנה את השם רק אם אינו `null` ואינו ריק, כולל לאחר הסרת רווחים בתחילתו ובסופו.
3. `setPrice(double price)` משנה את המחיר רק אם הוא גדול מ-0.
4. `setStock(int stock)` משנה את המלאי רק אם הכמות אינה שלילית.
5. `sell(int quantity)` מפחיתה את הכמות מהמלאי רק אם `quantity` חיובית ויש מספיק יחידות זמינות.
6. `getInfo()` מחזירה `String` עם מספר המוצר, שמו, מחירו והכמות במלאי.
7. `getNextId()` היא פעולה `static` שמחזירה את המזהה הבא שיוקצה, בלי ליצור מוצר.

**חשוב:** כל ה-`setters` והפעולה `sell` יחזירו `boolean` המצביע אם הפעולה הצליחה. אם פעולה נכשלת, אין לשנות את מצב האובייקט. אין לממש `setId()`.

## חלק ב: המחלקה `Store`

צרו מחלקה המייצגת חנות עם מספר מוגבל של מוצרים.

### שדות

| שדה | טיפוס | משמעות |
| --- | --- | --- |
| `storeName` | `String` | שם החנות |
| `products` | `Product[]` | המוצרים שנוספו לחנות |
| `soldCount` | `int[]` | מספר היחידות שנמכרו מכל מוצר |
| `productCount` | `int` | מספר המוצרים שנוספו בפועל |

כל השדות יהיו `private`.

המערכים יהיו באותו אורך. המוצר שנמצא בתא `i` במערך `products` מתאים למספר המכירות שבתא `i` במערך `soldCount`.

### בנאי

`Store(String storeName, int capacity)`

הבנאי יקבל את שם החנות ואת מספר המוצרים המקסימלי. אפשר להניח שהקיבולת המתקבלת חיובית. בתחילת הדרך החנות ריקה וכל ערכי המערך `soldCount` הם 0.

### פעולות

1. `addProduct(Product product)` מוסיפה מוצר למקום הפנוי הבא. הפעולה תיכשל אם המערך מלא, אם המוצר הוא `null` או אם אותו מזהה כבר קיים בחנות.
2. `findProductIndex(int id)` מחפשת מוצר לפי המזהה ומחזירה את האינדקס שלו. אם לא נמצא מוצר, מוחזר `-1`. **יש לממש את החיפוש באמצעות `while` ולהשתמש ב-`break` כשנמצא המוצר.**
3. `sellProduct(int id, int quantity)` מאתרת את המוצר, מבצעת מכירה באמצעות `sell` ומגדילה את התא המתאים ב-`soldCount` רק במקרה של מכירה מוצלחת. הפעולה מחזירה `boolean`.
4. `printAvailableProducts()` מדפיסה את פרטי המוצרים שיש להם לפחות יחידה אחת במלאי. **יש להשתמש בלולאת `for` וב-`continue` כדי לדלג על מוצרים שאזלו מהמלאי.**
5. `printSalesReport()` מדפיסה את שם החנות, ולאחריו את שמו של כל מוצר ומספר היחידות שנמכרו ממנו, גם אם כרגע אין ממנו מלאי.
6. `getTotalUnitsSold()` מחזירה את הסכום של כל הערכים הרלוונטיים במערך `soldCount` באמצעות לולאת `for`.

אין להחזיר את המערכים הפנימיים דרך `getters`, ואין לאפשר לקוד חיצוני לשנות את `productCount`.

## חלק ג: המחלקה `Main`

צרו מחלקה בשם `Main` ובה `main` המדגימה את התנהגות המערכת.

על התוכנית לבצע את כל הפעולות הבאות, לפי הסדר:

1. ליצור חנות עם קיבולת של **3 מוצרים**.
2. ליצור את המוצרים הבאים:

   | מוצר | מחיר | מלאי התחלתי |
   | --- | ---: | ---: |
   | Notebook | 12.5 | 3 |
   | Pen | 4.0 | 2 |
   | Bottle | 30.0 | 0 |

3. להוסיף את שלושת המוצרים לחנות ולוודא שכל ההוספות הצליחו.
4. ליצור מוצר רביעי ולנסות להוסיפו לחנות. ההוספה צריכה להיכשל כי החנות מלאה.
5. למכור 2 יחידות של `Notebook`.
6. לנסות למכור 3 יחידות של `Pen`. המכירה צריכה להיכשל כי אין מספיק מלאי.
7. למכור 2 יחידות של `Pen`. המכירה צריכה להצליח.
8. לנסות להגדיר מחיר `-5` לאחד המוצרים. יש לוודא שהמחיר הקודם נשמר.
9. להדפיס את כל המוצרים שעדיין זמינים במלאי.
10. להדפיס דוח מכירות ואת מספר היחידות הכולל שנמכרו.
11. להדפיס את מזהי המוצרים ואת המזהה הבא שיוקצה למוצר חדש.

**בדיקות צפויות:**

- לאחר פעולות המכירה, ל-`Notebook` תישאר יחידה אחת ול-`Pen` יישאר מלאי 0.
- רשימת המוצרים הזמינים תציג את `Notebook` בלבד.
- סך היחידות שנמכרו יהיה **4**.
- המכירה שנכשלה לא תשנה את המלאי או את נתוני המכירות.
- לכל מוצר יוקצה מזהה שונה, גם אם לא הצליחו להוסיף אותו לחנות.

אין חובה לעצב את הפלט בצורה מסוימת, אבל הוא חייב להיות ברור ולשקף אם פעולה הצליחה או נכשלה.

## חלק ד: שאלות הבנה

צרפו לקובץ התיעוד תשובות קצרות לשאלות הבאות:

1. מדוע צריך גם `Product[]` וגם `int[]`? מה שומר כל מערך?
2. מדוע צריך את `productCount` ולא מספיק להסתמך על אורך המערך?
3. מה ההבדל בין `nextId` לבין `id` מבחינת השימוש ב-`static`?
4. מדוע לא נכון לאפשר שינוי חופשי של השדה `stock` בלי בדיקת תקינות?
5. מה הבעיה האפשרית בהחזרת המערך הפנימי `products` מתוך `getter`?
6. מה ההבדל בין `break` לבין `continue` בפרויקט שלכם?

## כללי מימוש והגשה

- כל חלקי הפרויקט הם חובה.
- יש להשתמש בלולאות `for` ו-`while` ובפקודות `break` ו-`continue` בהתאם להנחיות.
- יש להשתמש במערכים רגילים בלבד. אין להשתמש ב-`ArrayList`, ב-`Streams`, בירושה או בפתרונות מתקדמים אחרים.
- אין צורך לקרוא קלט מהמשתמש. כל הבדיקות יכולות להופיע ישירות בתוך `main`.
- הקפידו על חלוקה למחלקות, שמות ברורים ובדיקת מקרי קצה.
- את הקוד יש לכתוב באופן עצמאי. מטרת התרגיל היא לתרגל את הנושאים שנלמדו בכיתה.
